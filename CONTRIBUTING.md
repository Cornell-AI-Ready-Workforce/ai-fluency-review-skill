# Contributing

Keep changes vendor-neutral, observable-behavior based, and suitable for non-technical readers.

Before opening a pull request:

1. Update the skill, reference, renderer, or example without duplicating guidance.
2. Run `mise run validate`.
3. Check the generated HTML at desktop and 390 px widths in light and dark themes.
4. Confirm that raw evidence, event summaries, source paths, and diff references are absent from the HTML source.
5. Describe any scoring or privacy implication in the pull request.

Do not add automated hiring recommendations, covert surveillance metrics, personality inference, or unsupported score calculations.
